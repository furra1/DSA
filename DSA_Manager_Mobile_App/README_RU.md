# DSA Manager — задания с количественным прогрессом

Проект сохраняет визуальный стиль прежнего DSA Manager (панель, группы, профиль, светлая/тёмная тема) и добавляет персональные задания с отчётом о выполненном объёме.

## Что добавлено

- Администратор/менеджер создаёт задачу вручную: название, описание, целевой объём (например, 500 листовок), срок, приоритет, группа и сотрудник.
- Сотрудник видит только свои задания в разделе «Задачи / Мои задания» на телефоне и в веб-версии.
- Сотрудник вводит текущее выполненное количество и нажимает «Сохранить». Прогресс сохраняется в SQL Server; руководитель видит актуальное значение при открытии задач/профиля.
- При достижении цели задача автоматически получает статус «Выполнена».
- В профиле сотрудника для руководителя доступен Excel-экспорт с ФИО, группой, задачами, целевым объёмом, фактическим выполнением и процентом.
- Регистрация сотрудника, первый запуск администратора, группы, профиль и переключение темы сохранены.
- При старте API выполняется только additive SQL upgrade: две новые колонки добавляются, если их нет. Существующие таблицы/данные не удаляются.

## Важно перед запуском

Сборка использует SQL Server и текущую структуру `dsa` из `database/DSA_Manager_SQL_Server_v1.sql`. Не удаляйте Docker volumes и не запускайте `docker compose down -v`.

## Обновление существующего VPS

1. Скопируйте архив на VPS и распакуйте в отдельную временную папку.
2. Проверьте, что в `/opt/dsa-manager/DSA_Manager_Mobile_App` есть `docker-compose.yml` (или `compose.yml`) и контейнеры проекта.
3. Из распакованной папки запустите `sudo ./deploy-update.sh`.
4. Скрипт создаёт архив резервной копии исходников, заменяет только `backend`, `frontend`, `Dockerfile` и `.dockerignore`, затем пересобирает только API. `.env`, compose-файл, SQL Server контейнер и volumes не трогает.
5. После успешного запуска проверьте `docker compose logs --tail=100 api`, затем полностью закройте и снова откройте Android-приложение.

Скрипт намеренно не удаляет данные и не заменяет конфигурацию секретов. Если сборка API не проходит, исходники резервируются в `/opt/dsa-manager/backups/`.

## Android

Android WebView-wrapper продолжает открывать опубликованный сайт. После обновления API/фронтенда приложение получает новый интерфейс через Service Worker cache v9. На телефоне полностью закройте приложение и запустите заново.

## Локальная сборка

Требуется .NET 8 SDK:

```bash
dotnet restore backend/DSAManager.API.csproj
dotnet build backend/DSAManager.API.csproj -c Release
```

Для деплоя на существующий сервер используйте `deploy-update.sh`, а не отдельный compose-файл, чтобы сохранить текущую БД и секреты.
